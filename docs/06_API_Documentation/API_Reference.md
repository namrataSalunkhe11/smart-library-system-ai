# API Reference Documentation

## Smart Library System with AI Recommendations

---

# 1. Introduction

## 1.1 Purpose

This document provides detailed technical information about the REST APIs used in the Smart Library System.

It describes available endpoints, request methods, authentication requirements, parameters, and response formats.

---

## 1.2 Base URL

Development Environment:

```text
http://localhost:5000/api
```

---

## 1.3 API Communication Format

The system uses:

| Feature        | Description |
| -------------- | ----------- |
| API Style      | REST        |
| Data Format    | JSON        |
| Authentication | JWT Token   |
| Protocol       | HTTP/HTTPS  |

---

# 2. Authentication

All protected APIs require a valid JWT token.

Token format:

```text
Authorization: Bearer <token>
```

---

# 3. HTTP Methods

| Method | Purpose              |
| ------ | -------------------- |
| GET    | Retrieve data        |
| POST   | Create new data      |
| PUT    | Update existing data |
| DELETE | Remove data          |

# 5. Authentication API Reference

## 5.1 Register User

### Endpoint

```text
POST /auth/register
```

### Description

Creates a new account for a user.

### Request Body

```json
{
    "name": "User Name",
    "email": "user@example.com",
    "password": "password",
    "role": "student"
}
```

### Response

```json
{
    "status": "success",
    "message": "User registered successfully"
}
```

---

## 5.2 Login User

### Endpoint

```text
POST /auth/login
```

### Description

Authenticates the user and generates an access token.

### Request Body

```json
{
    "email": "user@example.com",
    "password": "password"
}
```

### Response

```json
{
    "status": "success",
    "token": "jwt_token",
    "role": "student"
}
```

The API uses standard HTTP status codes to indicate request results.

| Status Code | Meaning                       |
| ----------- | ----------------------------- |
| 200         | Request successful            |
| 201         | Resource created successfully |
| 400         | Bad request                   |
| 401         | Unauthorized access           |
| 403         | Forbidden action              |
| 404         | Resource not found            |
| 500         | Internal server error         |

# 12. API Security Guidelines

## Authentication Security

The system implements:

* JWT-based authentication
* Secure password storage
* Token validation
* Session protection

---

## Data Validation

The API validates:

* User input
* Request parameters
* Data formats
* Required fields

---

## Access Control

API access is controlled according to user roles:

| Role          | API Access                                              |
| ------------- | ------------------------------------------------------- |
| Student       | Personal services, search, reservation, recommendations |
| Librarian     | Book operations, transactions, fine management          |
| Administrator | User management and reports                             |

# 13. API Development Guidelines

The following practices should be followed:

* Use meaningful endpoint names
* Maintain consistent response formats
* Validate all incoming requests
* Handle errors properly
* Document new APIs before implementation
