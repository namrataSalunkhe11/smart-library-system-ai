# API Reference Documentation

## Smart Library System with AI Recommendations

---

# 1. Introduction

## 1.1 Purpose

This document provides detailed technical information about the REST APIs used in the Smart Library System.

It describes the available endpoints, request methods, authentication requirements, parameters, access control, and response formats.

---

## 1.2 Base URL

Development Environment: http://localhost:5000

## 1.3 API Communication Format
| Feature           | Description  |
| ----------------- | ------------ |
| API Style         | REST         |
| Data Format       | JSON         |
| Authentication    | JWT Token    |
| Protocol          | HTTP/HTTPS   |
| Backend Framework | Python Flask |
| Database          | MySQL        |

# 2. Authentication
Protected APIs require a valid JWT access token.

The token must be sent in the HTTP Authorization header.

Authorization: Bearer <access_token>

The access token is generated after successful login.

# 3. HTTP Methods
| Method | Purpose              |
| ------ | -------------------- |
| GET    | Retrieve data        |
| POST   | Create new data      |
| PUT    | Update existing data |
| DELETE | Delete existing data |

# 4. Standard Response Structure
The Smart Library System uses JSON responses.

## 4.1 Success Response
Example:
{
    "success": true,
    "message": "Request completed successfully."
}
Some APIs return additional data along with the success status.

Example:

{
    "success": true,
    "recommendations": []
}

## 4.2 Error Response

Example:

{
    "success": false,
    "message": "Error description."
}

JWT authentication errors may also return:

{
    "msg": "Missing Authorization Header"
}

## 5.2 Register User
Endpoint
POST /api/auth/register
Authentication

Not required.

Description

Creates a new user account in the system.

Request Body
{
    "first_name": "Test",
    "last_name": "Student",
    "email": "test.student@library.com",
    "password": "password123",
    "role_id": 3
}
Required Fields
| Field      | Description         |
| ---------- | ------------------- |
| first_name | User first name     |
| last_name  | User last name      |
| email      | User email address  |
| password   | User password       |
| role_id    | ID of the user role |

Example Success Response
{
    "success": true,
    "message": "User registered successfully."
}
## 5.3 Login User
Endpoint
POST /api/auth/login
Authentication

Not required.

Description

Authenticates a registered user and generates a JWT access token.

Request Body
{
    "email": "test.student@library.com",
    "password": "password123"
}
Required Fields
| Field    | Description              |
| -------- | ------------------------ |
| email    | Registered email address |
| password | User password            |

Example Response

The response contains the authentication information and JWT token generated by the system.

{
    "success": true,
    "message": "Login successful.",
    "access_token": "<JWT_TOKEN>"
}

# 7. Issue Transaction API

## 7.1 Issue Book
Endpoint
POST /api/issues
Authentication

Required.

Access

Admin and Librarian.

Description

Request Body

    "user_id": 9,
    "copy_id": 2

Required Fields
| Field   | Description                       |

    "success": true,
    "message": "Book issued successfully.",
    "transaction_id": 1,
    "due_date": "2026-08-15"

{
    "success": false,

}

# 8. AI Recommendation API

## 8.1 Get Book Recommendations
Endpoint
GET /api/recommendations/<user_id>
Authentication

Required.

Access Control

A Student can access only their own recommendations.

Admin and Librarian users can access recommendations for other users.

Description

Returns personalized book recommendations based on the user's borrowing history.

The recommendation system considers factors such as:

User borrowing history
Frequently borrowed categories
Previously borrowed authors
Available books
Books already borrowed by the user
Recommendation score

## 8.2 Example Request

For user ID 9:

GET http://localhost:5000/api/recommendations/9

The request must include a JWT token:

Authorization: Bearer <JWT_TOKEN>

## 8.3 Example Response
{
    "recommendations": [
        {
            "author": "Robert C. Martin",
            "book_id": 2,
            "category": "Computer Science",
            "publisher": null,
            "recommendation_score": 3,
            "title": "Python Programming"
        },
        {
            "author": "Andrew S. Tanenbaum",
            "book_id": 12,
            "category": "Computer Networks",
            "publisher": "Pearson",
            "recommendation_score": 1,
            "title": "Computer Networking: A Top-Down Approach"
        }
    ],
    "success": true
}

## 8.4 No Borrowing History

If a user has never borrowed a book, the API returns:

{
    "message": "No borrowing history found.",
    "recommendations": [],
    "success": true
}

## 8.5 Unauthorized Access

If a Student tries to access another user's recommendations, the API returns:

{
    "success": false,
    "message": "You can only access your own recommendations."
}

HTTP Status:

403 Forbidden
8.6 Missing Authentication

If the JWT token is not provided, the API returns:

{
    "msg": "Missing Authorization Header"
}

HTTP Status:

401 Unauthorized

# 12. API Security

## 12.1 JWT Authentication

Protected endpoints use JSON Web Tokens for authentication.

The token is supplied through:

Authorization: Bearer <JWT_TOKEN>

## 12.2 Role-Based Access Control

The system uses role-based access control.
| Role          | Description                                                                  |
| ------------- | ---------------------------------------------------------------------------- |
| Student       | Can access personal services, book search, transactions, and recommendations |
| Librarian     | Can manage books, issue books, return books, and manage library operations   |
| Administrator | Has administrative access to system operations                               |

## 12.3 Recommendation Access Control

Recommendation data is protected using the authenticated user's identity.

Students cannot request recommendations belonging to another user.

Admin and Librarian users can access recommendations for other users when permitted by the system.

## 12.4 Input Validation

The API validates:

Required fields
Request body
User input
IDs
Search queries
JSON format

Invalid requests return appropriate error messages.

# 15. AI Recommendation Logic

The Smart Library System uses a rule-based recommendation approach to provide personalized recommendations.

The recommendation process follows these steps:

## Step 1: Identify Borrowing History

The system checks the books previously borrowed by the authenticated user.

## Step 2: Identify Preferred Categories

The system calculates the categories associated with the user's borrowing history.

## Step 3: Identify Previously Borrowed Authors

The system checks authors whose books were previously borrowed by the user.

## Step 4: Find Available Books

The system searches for available books that the user has not already borrowed.

## Step 5: Calculate Recommendation Score

Books receive a score based on user preferences.

For example:
| Condition                               | Score |
| --------------------------------------- | ----: |
| Same author as previously borrowed book |    +2 |
| Belongs to preferred category           |    +3 |

## Step 6: Sort Recommendations

Books with higher recommendation scores are displayed first.

This approach provides a simple and explainable AI-based recommendation feature suitable for the Smart Library System.
