# Bug Report Template

## Smart Library System with AI Recommendations

---

# 1. Introduction

## Purpose

This document defines the standard format used for reporting, tracking, and resolving software defects found during testing of the Smart Library System.

A structured bug reporting process helps developers understand issues and implement effective fixes.

---

# 2. Bug Report Format

| Field         | Description                     |
| ------------- | ------------------------------- |
| Bug ID        | Unique identifier for the bug   |
| Bug Title     | Short description of the issue  |
| Module        | Affected system module          |
| Reported By   | Person who identified the issue |
| Date Reported | Date of reporting               |
| Severity      | Impact level of the issue       |
| Priority      | Fix urgency                     |
| Status        | Current bug state               |

---

# 3. Bug Details Template

## Bug ID

Example:

```text id="f5q8m3"
BUG-001
```

---

## Bug Title

Short and clear description of the problem.

Example:

```text id="v7n2k4"
Login fails with valid credentials
```

---

## Module

Affected module:

```text id="m8p3x6"
Authentication
Book Management
Transaction
Reservation
AI Recommendation
```

---

## Description

Detailed explanation of the issue.

---

## Steps to Reproduce

1. Open application
2. Navigate to affected feature
3. Perform required actions
4. Observe the issue

---

## Expected Result

Describe the correct system behavior.

---

## Actual Result

Describe the behavior observed during testing.

---

# 4. Bug Classification

## Severity Levels

| Severity | Description                                 |
| -------- | ------------------------------------------- |
| Critical | System failure or major functionality issue |
| High     | Important feature not working               |
| Medium   | Feature works with limitations              |
| Low      | Minor issue or UI problem                   |

---

## Priority Levels

| Priority | Description             |
| -------- | ----------------------- |
| High     | Fix immediately         |
| Medium   | Fix in upcoming release |
| Low      | Fix when possible       |

---

# 5. Bug Status

| Status      | Meaning                    |
| ----------- | -------------------------- |
| Open        | Issue reported             |
| In Progress | Fix is being developed     |
| Resolved    | Fix completed              |
| Closed      | Fix verified and completed |

# 7. Conclusion

The Bug Report Template provides a consistent method for documenting software issues and ensures effective communication between testers and developers.
